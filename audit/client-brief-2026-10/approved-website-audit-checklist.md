# A Textured Word — approved website acceptance checklist

**Baseline.** This checklist uses only `Muhib notes #3 (2).pdf` and `website_changes_for_approval (3).pdf`, plus Muhib's confirmation that Aneesa approved the proposed changes and the referenced recordings are available. The two PDFs form one approved brief: the notes supply copy and exact terms; the changes PDF supplies the approved implementation direction. Source references below are for traceability, not separate approval states.

**Source key:** `N1` / `N2` = notes pages 1 / 2. `C1`–`C4` = changes pages 1–4. The recordings themselves were not reviewed to make this checklist; claims drawn from them are based on the approved changes PDF. No other local documents were used.

**Audit rule.** For each ID, inspect the *running site* at phone and desktop widths and report `PASS`, `FAIL`, or `UNVERIFIABLE`, with URL, observed evidence, and a screenshot or test result where useful. `UNVERIFIABLE` means the auditor has not inspected the required evidence; it does not mean approval is pending. Code presence alone is not a pass. An unpassed required item prevents a claim of brief compliance.

## Release gate and report format

1. Compare all supplied copy with the rendered notes PDF. Report exact omissions, rewrites and unsupported additions.
2. Walk every service route on phone and desktop. Test each live link, audio player and enquiry option.
3. Match every public fact, credential, status, price, testimonial, portfolio item and service promise to approved evidence. A fabricated claim is a failure even if the page looks good.
4. Return one result per ID. Attach URL, observation and screenshot/test result. Do not collapse failed items into a general score.
5. Claim brief compliance only when every required item passes and no unsupported additions remain. Identify the site version/commit and audit date.
